# D002 — 지도와 이동 공급자 검토

- 상태: **검토 중 / 저장 허용 계약·공급자 검증 대기. 공급자 미확정.**
- 조사일: 2026-10-06 (Asia/Seoul).
- 관련 Task: T02, T03, T04, T07, T08, T13.
- 관련 요구: R02, R04–R05, R08–R12, R15–R17, U02, U04.
- 선행: [D001](D001-플랫폼과-데이터.md). T01 PR #1은 main에 병합됐다.

## 사용자 방향과 조사 기준

2026-10-06 T02 재개 지시로 **검색한 장소를 바로 저장하고 오프라인에서 확인하는 기존 요구를 유지**한다. 입력 흐름 유지 여부는 더 이상 미결정이 아니다. 수동 주소/좌표 재입력, 지도 재선택을 필수로 바꾸거나 공급자를 임의 확정하지 않는다. 오프라인 지도·신규 검색·경로 조회를 추가하는 지시도 아니다.

확인 시점: main `e0df54355dbb1c6c29e24cca9c009a50328ee77e`, 이번 재개 직전 작업 브랜치 `6f35102503e66461c3db180cbc601de2826aa29a`, [PR #2](https://github.com/danhk0612/DK-Travel-Helper/pull/2)는 열린 초안이다. 제품 코드·계정 생성·유료 설정·문의 발송·병합은 이번 범위 밖이다.

확인 수준은 (1) 공식 적용 약관 전문, (2) 공식 공지/가이드/가격표, (3) 다른 서비스에 대한 담당자 답변, (4) 이 앱에 적용할 때의 추론/미확인으로 구분한다. 공개 안내가 개별 계약 승인이나 실제 연결 검증을 대신하지 않는다.

## 판단

현재 공개 조건만으로 네이버/카카오 검색 결과를 여행의 영구 장소 데이터와 IndexedDB 사본으로 저장하는 구조를 확정할 수 없다. 이는 R02/R05의 검색 후 바로 추가, D001의 서버 원본·오프라인 열람과 직접 연결된다. 조회 가능 여부와 저장 허용 여부는 별개다.

카카오 최신 API 문서에는 도보·대중교통 조회가 있다. 예전 FAQ의 “길찾기 REST API 미제공”은 현재 기능 판단에 적용하지 않는다. 그러나 최근 담당자 답변은 사용자가 선택한 장소명·좌표와 가공 데이터의 저장도 제한한다. 사용자 확정 버튼이나 재선택만으로 저장 가능한 자체 데이터가 된다고 가정하지 않는다.

네이버 검색은 신규 이용 경로가 NAVER API HUB로 이관됐다. 기존 개발자센터의 무료 25,000회/일 안내만으로 신규 앱을 설계하지 않는다. 장기 여행 저장은 임시 캐시 예외로 확인되지 않았다. HUB 상품 페이지가 연결한 2026-09-20 시행 약관 전문을 확보했으며, 검색 결과 장기 보관의 허용 근거는 없다. 10월 7일 개정 공지와 개정 후 전문은 구분한다.

**권장 방향은 핵심 입력 흐름을 유지하고, 이를 허용하는 공급자 조건/별도 계약 또는 대체 공급자를 검토하는 것**이다. 현재 두 공급자 중 하나를 확정하거나 수동 재입력으로 요구를 바꾸지 않는다. Geoapify/OSM 계열은 아래와 같이 저장 허용 근거가 있는 후보로 검토했으나, 한국 검색 품질·등급 운영·라이선스 적용과 역할별 선택은 미확정이다.

### 네이버 — HUB와 Maps 분리

HUB 개요에서 검색 통합 월 775,000건, 키당 50 RPS, 무료 기간 증설 불가·한도 도달 차단을 재확인했다. 한시적 무료이며 유료 전환일/단가는 발표되지 않았다. 상품 요금표도 월 775,000건과 일 최대 25,000건을 함께 적는다. 반면 개요 FAQ는 일 단위가 아닌 월 단위 관리라고 명시하므로 공식 문구 충돌은 남아 있다. 일 제한이 폐지됐다고 확정하지 않는다. 지역 결과 최대 5개·start=1은 검색 품질/탐색 범위 검증 대상이다.

Maps 상품 페이지의 현재 공개 데이터와 공식 한국 리전 요금표를 2026-10-06에 직접 받아 읽었다. 검색 색인만으로 숫자를 확정하지 않았다. HTML 본문에 생략된 내용은 페이지의 공개 JSON 데이터에서 해당 상품/한국 리전 레코드를 대조했다.

| Maps 역할 | 게시표·동적 원본 대조 단가(원/건, VAT 별도) | 대표 계정 월 무료량 |
| --- | ---: | ---: |
| Web Dynamic Map | 0.1 | 6,000,000 |
| Static Map | 2 | 3,000,000 |
| Geocoding | 0.5 | 3,000,000 |
| Reverse Geocoding | 0.5 | 3,000,000 |
| Directions 5 | 5 | 60,000 |
| Directions 15 | 20 | 3,000 |

확인 범위: 위 단가는 공식 한국 게시표와 현행 Maps 상품 페이지가 사용하는 동적 가격 원본을 독립 대조했다. `price-tag` 렌더러가 조회하는 한국/공통 KRW 공개 GET 응답을 확인했으며 Maps 요금은 공통 응답에 있었다. 상품 페이지의 `SPOPAPI000000001`·`MTRAT` 및 MPWEB/MPSTC/MPGEO/MPREV/MPDIR/MPDR2, REP/GEN 속성을 그대로 매칭하고 유효 기간과 `periodUnitList`의 초과 구간을 대조했다. 각각 0.1/2/0.5/0.5/5/20원으로 게시표와 일치한다. **동적 표시 단가 미확인은 해소**됐다. 무료량은 상품 페이지/가이드 근거이며, 응답의 REP 무료량 경계 아래에도 유료 단가가 들어 있어 이 원본만으로 무료 청구를 계산하지 않는다. 내부 productCode의 명칭이 AI·NAVER API라고 해서 신규 Maps가 구상품으로 바뀌었다고 해석하지 않는다. 실제 신규 계약의 상품·대표 계정 자격·무료량 적용·청구·비용 차단은 여전히 미검증이다. 실제 선택 시 최신 가격표/계산기로 적용 상품·구간·계정·세금을 다시 확인한다. 모바일 가격 페이지에는 다른 리전/과거 상품 데이터도 함께 있으므로 Web 1,000만 건이나 Mobile 무료 문구를 한국 신규 PWA 조건으로 가져오지 않는다.

대표 계정은 개인 전화번호/사업자번호 기준 1개이며 비대표 계정은 무료량이 적용되지 않는다는 공식 가이드를 확인했다. 실제 계정 자격과 비용 차단/월 한도 설정은 미검증이다. 기존 **AI·NAVER API 내 지도 상품**의 무료량 중단과 새 **Maps** 상품을 구분한다. Maps 요금을 내는 것과 HUB 검색 결과 저장권은 별개다.

### HUB 적용 약관 — 현재와 예정 개정

- **현재 전문 확보:** HUB 상품 페이지의 약관 링크 PDF, 시행 2026-09-20. 일반조건 1은 네이버와의 API 약관에 NCP 플랫폼 약관도 함께 적용한다고 설명한다. 개발자센터 약관을 대신 사용하지 않았다.
- 일반조건 7.2③은 API 이용 대가 수취를 제한하고, 7.3③은 허용 범위를 넘는 복제·저장·가공·배포와 지역정보 별도 DB 관리 등을 제한한다.
- 검색 특약 1.1–1.3은 검색결과 제공 목적·출처/원본 링크·표시 조건과 원본/파생 데이터의 저장 및 수익 활용 제한을 둔다. 1.4의 예외는 기기 및 서버 개인화 캐시를 24시간과 새 질의 중 짧은 기간, 서버 이력 캐시를 최대 21일로 제한한다. **판단:** 서버 여행 원본과 장기 오프라인 사본의 근거로 사용할 수 없다.
- **개정 공지 전문 확보:** 2026-10-01 게시, 2026-10-07 시행, 공지 #2271. 전후 비교는 약관 이름·목적, 9.3, 10.1–10.4, 13.2의 통지/책임 문구다. 비교표에 7장이나 검색 특약의 저장 허용 변경은 없다.
- **미확인:** 개정 후 약관 전문 및 실제 가입 시 적용 문서. 이번 재조회에서도 상품 페이지의 실제 약관 링크는 동일한 9월 20일 PDF였고, 약관 목록/공지 공개 데이터에서도 10월 7일 전문을 확보하지 못했다. 파일명·시행일을 추측해 URL을 만들어 대체하지 않는다. 공지 비교표로 새 전문 전체를 확보했다고 보고하지 않는다. 10월 6일에는 예정 개정을 시행 중이라고 표현하지 않는다. 저장권 확대가 생겼다는 근거도 없다.

### Maps 약관 — 요금과 별개인 저장 제한

NCP 약관 목록에서 연결한 Maps 약관 전문(2025-03-20 시행)을 직접 읽었다. 제7조⑨는 사전 동의 없이 허용 범위를 넘는 저장/가공/배포를 제한하고, ⑪는 Maps 응답을 즉시 한 번 이용하는 범위를 넘어 별도 저장·DB화·재사용하는 것을 금지한다. 좌표 결과를 모아 이후 API 호출 없이 재사용하는 예도 포함된다. Geocoding·Directions 응답을 유료로 호출해도 그 요금이 장기 보관권을 뜻하지 않는다.

제6조의 고객 관리 데이터 백업은 제7조⑪의 공급자 결과 저장 금지를 해소하는 조항으로 해석하지 않는다. **따라서 HUB 검색 대신 Maps 주소 변환 결과를 저장하는 것만으로 현재 차단을 해결할 수 없다.** 독립된 허용 데이터의 온라인 지도 표시 가능 범위는 별도 확인한다.

| 카카오 실시간 결과를 다른 지도에 표시 | 최근 안내는 REST 조합 자체를 제한하지 않는다고 설명 | 결합 가능성이 저장 허용을 뜻하지 않음. 선택한 데이터별 계약을 별도 확인 |
| Maps 좌표·경로 결과 및 카카오 경로 시간·단계·좌표 | Maps 제7조⑪의 저장 금지, 카카오 담당자 원본/가공 저장 제한. 개별 보관 허가 없음 | 저장 교통 정보에 API 응답을 자동 복사하지 않음. 사용자 직접 기록과 구분 |

| 무료/유료 등급별 장소 한도 | 카카오의 API 기능 별도 과금 제한, 네이버 검색의 수익 활용 제한 확인 필요 | 앱의 저장/관리 등급 정책이 지도/검색 판매로 해석되는지 공급자 확인. 허용을 추정하지 않음 |

HUB 약관의 임시 캐시와 여행 데이터 영구 저장은 다른 용도다. 검색 목록 전체를 저장하지 않고 선택한 몇 개만 저장해도 허가가 생긴다고 추정하지 않는다.

카카오 담당자 스레드는 일부 저장 해석이 정정됐고 유료 서비스 조건에는 개별 설명을 요구한다. 8월 20일 #2는 재선택 좌표도 실질적인 검색 결과 재사용이면 불허한다고 정정했다. 그런데 #3의 조건 6은 다른 지도에서 저장 위치를 재선택하는 흐름을 다시 포함하고, 8월 21일 #4는 제시된 조건 전체에 포괄적으로 허용 답변했다. **문구 충돌:** #4가 조건 6까지 허용하거나 앞선 정정을 철회했는지 명시하지 않아 적용 관계가 불명확하다. #3의 조건 5는 원본/가공 응답 비저장이므로 검색→즉시 저장을 허가받은 사례로 쓸 수 없다. 이 앱의 저장/오프라인 사본·등급 한도에 대한 개별 허가도 없다. 정정과 마지막 답변을 함께 제시하고 재선택 우회·저장 금지 철회 어느 쪽도 확정하지 않는다. 별도 유료 호출 설정도 저장 라이선스가 아니다.

## 키·인증·서버 역할 제안

- Google 사용자 로그인과 지도 공급자의 앱 키는 별개다.
- 웹 SDK는 지정 JavaScript/웹 키와 등록한 사이트 origin을 사용한다. REST 비밀 키는 브라우저 번들/Vite 공개 환경 변수/Git에 넣지 않는다.
- 비밀 키가 필요한 검색·경로 API를 선택하면 로그인된 요청을 받는 최소 서버 중계가 필요하다. 선택 공급자의 CORS·인증·호출 제한·허용 origin 조건을 확인한 뒤 구현 계약을 만든다. Supabase Edge Function 등 런타임은 아직 선택하지 않았다.
- 프록시가 있더라도 결과의 저장·재배포 제한은 그대로 검토한다. 키를 감추는 기능으로 데이터 사용권 문제가 해결되지 않는다.
- 지도 엔진·공급자 플러그인·상시 범용 서버를 만들지 않는다. 외부 링크만 사용하는 역할은 내부 API 연동과 분리한다.

## 핵심 흐름을 유지하는 대안 — 선택하지 않음

| 대안 | 확인된 근거 | 미확인/재개 조건 |
| --- | --- | --- |
| 네이버 HUB/Maps 또는 카카오의 별도 보관 허가/계약 | 현재 표준 조건·담당 안내는 핵심 저장 흐름과 충돌 | 이런 예외 계약의 판매 여부·승인 가능성·비용 자체가 미확인. 서버/Android 사본·필드·기간·등급별 저장 한도·다른 지도 표시·계약 종료 후 보존을 명시적으로 허가받아야 함 |
| Geoapify Geocoding/Places | 공식 Geocoding 안내는 주소/위치 저장, Places FAQ는 결과 캐시·저장·재배포 허용을 명시 | 한국 주소/상호/별칭·POI 누락과 좌표 품질 미검증. Geocoding의 자유형 검색/amenity 이름과 Places의 선택적 name 필터가 있으나 한국 검색 품질의 증거는 아님. Places의 카테고리+영역 검색을 임의 장소명 검색과 동일시하지 않음. UI를 카테고리 선택만으로 축소하지 않음 |
| OSM 데이터 기반 자체/관리형 검색 | ODbL은 출처 표시 등 조건하에 복사·배포·변형을 허용 | 파생/집합 DB와 공개 이용의 라이선스 경계·한국 데이터 품질·운영 비용 검토 필요. 자체 검색 서버 도입은 D001 운영 영향이 있어 사용자 선택 전 확정하지 않음 |

Geoapify Free는 3,000 credits/일·최대 5 requests/초, API 10은 월 $59·10,000 credits/일·최대 12 requests/초다(월 결제 USD 게시값, 세금 별도). 요금 FAQ는 **무료 상용 웹/앱의 운영 가능**, 한도·기능 제한·출처 표시 준수 시 상용이라는 이유만으로 유료 플랜이 필요하지 않다고 명시한다. 반면 약관 v5(2024-02-02)의 Plans and usage limits는 운영 단계의 제한과 별도 확인을 요구한다. 이전의 “무료 상용 운영 근거 미확보”보다 근거는 보강됐지만 **두 공식 문구의 적용 관계·이 앱 등급 차등/해지 후 보존은 미확인**이다. 유료 플랜도 한국 검색 품질이나 개별 등급 계약을 보장하지 않는다.

Geocoding/주소 자동완성은 각각 1 request=1 credit. Places는 limit 20 이하 1 credit, 그 초과는 기본 1 credit에 반환 결과 20개마다 추가 credit이라는 공식 설명이다. 지도 타일·경로도 같은 플랜 크레딧을 사용하므로 3,000 credits가 항상 3,000 장소 검색을 뜻하지 않는다. 일 한도는 soft limit이며 즉시 차단을 보장하지 않고, 약관은 초과 시 정지 또는 추가 과금 가능성을 둔다. 무료 비용 상한을 보장하는 계약/설정은 미검증이다. 다수 계정/프로젝트 분산으로 낮은 플랜 한도를 우회할 수 없다.

Geoapify의 저장 허용 안내는 호출량과 저장 개수를 구분한다. 공개 안내에서 결과별 추가 저장 요금·저장 기간 한도를 찾지 못했으며 Places FAQ는 저장/재배포에 추가 제한이 없다고 한다. 따라서 앱 한도 3/50·15/150·50/300 자체가 API 호출 플랜을 결정하지 않는다. 다만 이런 앱 유료 등급을 개별 승인한 자료는 없다. 모든 플랜에서 OSM 출처 표시, Free에서 Geoapify 링크 표시, API/응답별 추가 출처를 따라야 한다. Geocoding은 OSM 외 여러 데이터셋도 사용하므로 전체 결과를 ODbL 하나로 처리하지 않는다. 서비스 접근 라이선스의 양도/재허락 제한과 결과 저장 안내도 구분한다.

OSM 출처 데이터의 저장 허용과 앱의 모든 코드/개인 메모 공개 의무는 동일하지 않다. OSMF 이사회 승인 Geocoding Guideline은 개별 지오코딩 결과가 비실질적 추출이며, **지오코더가 사용하는 원본 OSM DB를 수정하지 않았거나 사소한 변환만 했고, 결과로 원본의 전부/실질적 부분을 새 DB로 집계하지 않는 두 조건**에서 자체/제3자 데이터와 영구·임시 저장할 수 있다고 설명한다. 공급자 수정 DB가 첫 조건에 해당하는지 확인하지 않은 채 이 예외를 모든 Geoapify 결과에 일반화하지 않는다. 서버/기기 캐시를 타 지도에 표시하는 사례도 있다. **판단:** 여행별 선택 결과의 저장을 검토할 구체 근거이며, 전체 개인 메모를 공개해야 한다고 단정할 이유는 없다. 다만 이 앱 전체 집계가 해당 조건을 충족하는지, Places 카테고리 추출·추가 필드/ID·공급자 수정 DB까지 같은 해석을 적용할 수 있는지는 별도 검토한다.

ODbL §3은 상업적 이용을 포함한 복사/이용/배포를 허용한다. §4.4–4.6은 공개 이용하는 파생 DB의 동일 라이선스·기계 판독 사본/변경분 제공 조건을 정하고, §4.5는 집합 DB의 독립 부분과 조직 내부 이용 경계를 둔다. §4.7은 수신자의 라이선스 권리를 추가 조건/기술 조치로 제한하지 못하게 하며, 인증 환경도 허용 조건이 있다. **판단:** 등급별 여행/장소 보관 서비스 한도는 검토 가능하나 OSM 데이터 수신자의 재사용권을 별도 금지하는 계약과 혼동하지 않는다. ODbL §1의 실질성은 양뿐 아니라 질도 고려하며 비실질적 부분의 반복·체계적 추출이 실질적 추출이 될 수 있다. 계정별 150/2,250/15,000곳이라는 초기 최대치(여행 수×장소 수)는 호출량이나 실질성 판정 기준이 아니며, 관리자 변경·전체 이용자 집계를 고려해야 한다. 이 산술값은 허용 한도 확정이나 기능 추가가 아니다. 개인 여행 서버를 “조직 내부 이용”으로 자동 분류하지 않는다. 과금·등급에 대한 최종 적용 검토는 미완료다.

ODbL §9의 사용권은 위반에 따른 종료 조건을 제외하면 데이터 권리의 지속 근거가 있다. 이는 OSM 데이터 라이선스에 관한 것이며 Geoapify 구독 해지 후 모든 혼합 출처 결과에 동일한 보존권이 있다고 입증하지 않는다. 온라인/오프라인 정보 화면의 출처와 라이선스 안내를 유지할 계약이 필요하다. OSM 측 타 지도 표시 근거와 네이버/카카오 지도 측 표시 허용은 양쪽에서 확인한다.

OSMF의 공용 Nominatim은 **앱 전체 최대 1 request/초**, 식별 가능한 Referer/User-Agent, 출처 표시·캐시·서비스 교체 가능 조건, 자동완성 금지·체계적 수집 금지 등이 있다. 라이선스가 개방돼 있다는 이유로 무제한 무료 검색 서버로 선택하지 않는다. Nominatim 정책은 자체/다른 회사 인스턴스에는 동일하게 적용되지 않는다. 무료 공용 서버를 범용 검색 서비스로 자동 채택하지 않는다.

Geoapify/OSM에서 독립적으로 받은 결과를 저장하는 안은 검토 가능하다. 네이버/카카오 제한 응답을 다른 이름으로 저장하거나 재조회·지도 재선택으로 출처를 지우는 방식은 대안으로 채택하지 않는다. 네이버 우선 외부 길찾기는 별도 역할 후보이며 검색 공급자 교체가 곧 외부 연결 변경을 뜻하지 않는다. 내부 도보/대중교통과 예정 경로 표현도 아직 미확정이다.

## 한국 검색 품질과 운영 검증 — 미실행

| 후보 | 공식 문서에서 확인한 기능 | 아직 확인하지 못한 것 |
| --- | --- | --- |
| Geoapify Geocoding | 자유형 text·구조화 name, amenity 유형, 국가 필터·언어·근접 우선, 주소/좌표·result_type·confidence 반환 | 한국 도로명/지번 해석, 특정 상호·동명이점·옛 이름/별칭 적중, 최신 POI와 실제 입구/건물 위치 정확도 |
| Geoapify Places | OSM POI, 필수 categories와 filter 또는 bias, 선택적 name 매칭·언어·페이지 조회 | 임의 이름만으로 충분한 검색, 한국 별칭/오타 처리와 누락률. name 필터 존재가 범용 키워드 검색 보장을 뜻하지 않음 |
| OSM 기반 Nominatim | 자유형 q/구조화 amenity·주소, 국가 필터, 결과 언어·namedetails | 한국 데이터 완전성·주소 파싱/별칭 적중. namedetails 반환과 별칭 검색 성공은 별개. Geoapify는 다른 엔진/복수 데이터이므로 Nominatim 결과로 대체 검증 불가 |

공식 자료의 worldwide·다국어 지원은 한국 여행 서비스에 충분한 검색 품질의 증거가 아니다. 한국 적중률/오차를 입증하는 공식 벤치마크는 이번 공식 문서와 한국 품질 추가 검색에서도 확보하지 못했다. `lang=ko`는 표시 언어 옵션이며 `rank.confidence`/`match_type`은 공급자의 매칭 지표다. 정답 시설·좌표와 독립 비교하지 않은 점수는 한국 품질 합격 근거가 아니다. 품질이 낮다고도 단정하지 않는다. 계정/키 생성·실제 검색 요청·공개 데모 실행·Android 확인을 하지 않았으므로 결과 표를 성공/실패로 채우지 않는다.

후속 검증을 허용받는 경우의 표본 제안: 수도권/춘천/경주에서 도로명·지번, 역/관광지 정식명, 카페/음식점/숙소 상호, 동명이점, 옛 이름·약칭, 띄어쓰기/오타를 포함한다. 예를 들어 서울역, 춘천역, 김유정역, 경주역/신경주역, 첨성대, 동궁과 월지/안압지 등을 비교하되 기대 장소·주소/좌표는 독립된 공식 시설 자료로 확인한다. 표본/허용 오차·성공 기준은 검증 전에 정하며 이번에 확정하지 않는다. 공급자·조회일·질의·상위 결과·주소·좌표·출처·예상 장소와의 일치를 기록하고, 서로 다른 시설로 매칭된 사례와 미검색 사례를 별도로 남긴다. 이 제안은 수동 주소 재입력을 제품 흐름에 추가하는 것이 아니다.

공용 Nominatim의 운영 한도는 사용자 한 명당이 아니라 앱 전체다. 상용 유료 이용자에게 가용성을 보장하지 않으며 제공 철회/정책 변경 위험도 명시돼 있다. 자체/관리형 인스턴스는 검색 DB/인덱스·한국 데이터 갱신·저장/백업·호스팅 비용과 책임이 별도로 필요하다. OSM 라이선스의 무료 데이터가 무료 운영을 보장하지 않는다. D001의 상시 서버 불필요 결정에 영향을 주는 자체 운영은 사용자 선택 없이 도입하지 않는다.
