# D002 — 지도와 이동 공급자 검토

- 상태: **검토 중 / 사용자 방향 결정 및 보관 조건 확인 대기. 공급자 미확정.**
- 조사일: 2026-10-06 (Asia/Seoul).
- 관련 Task: T02, T03, T04, T07, T08, T13.
- 관련 요구: R02, R04–R05, R08–R12, R15–R17, U02, U04.
- 선행: [D001](D001-플랫폼과-데이터.md). T01 PR #1은 main에 병합됐다.

## 판단

현재 공개 조건만으로 네이버/카카오 검색 결과를 여행의 영구 장소 데이터와 IndexedDB 사본으로 저장하는 구조를 확정할 수 없다. 이는 R02/R05의 검색 후 바로 추가, D001의 서버 원본·오프라인 열람과 직접 연결된다. 조회 가능 여부와 저장 허용 여부는 별개다.

카카오 최신 API 문서에는 도보·대중교통 조회가 있다. 예전 FAQ의 “길찾기 REST API 미제공”은 현재 기능 판단에 적용하지 않는다. 그러나 최근 담당자 답변은 사용자가 선택한 장소명·좌표와 가공 데이터의 저장도 제한한다. 사용자 확정 버튼이나 재선택만으로 저장 가능한 자체 데이터가 된다고 가정하지 않는다.

네이버 검색은 신규 이용 경로가 NAVER API HUB로 이관됐다. 기존 개발자센터의 무료 25,000회/일 안내만으로 신규 앱을 설계하지 않는다. 장기 여행 저장은 임시 캐시 예외로 확인되지 않았다. HUB의 최신 적용 약관을 추가 확인해야 한다.

**권장 방향은 핵심 입력 흐름을 유지하고, 이를 허용하는 공급자 조건/별도 계약 또는 대체 공급자를 검토하는 것**이다. 현재 두 공급자 중 하나를 확정하거나 수동 재입력으로 요구를 바꾸지 않는다. 대체 공급자의 성능·비용·저장 조건은 아직 조사/확정하지 않았다.

## 요금·쿼터 조사

### 카카오 — 현재 문서에서 확인

| 역할 | 무료 일간 쿼터 | 추가 쿼터 단가 |
| --- | ---: | ---: |
| 웹 지도 SDK | 300,000건 | 0.1원/건 |
| 주소→좌표 | 100,000건 | 0.5원/건 |
| 키워드 장소 검색 | 100,000건 | 2원/건 |
| 도보 경로 | 1,000건 | 10원/건 |
| 대중교통 경로 | 1,000건 | 10원/건 |

무료 쿼터는 개발자 계정에서 카카오맵을 처음 활성화한 앱에만 적용된다. 월간 전체 API 무료 쿼터 3,000,000건과 API별 일간 제한을 함께 확인해야 한다. 두 번째 활성화 앱 또는 무료량 초과는 비즈월렛·유료 API 설정 조건이 있다. 기존 계정의 적용 앱 여부는 확인하지 않았다. 카카오모빌리티 자동차 API 단가·계약은 이번 조회에서 원문을 확인하지 못해 미검증이다. 유료 설정·비용 지출을 하지 않았다.

### 네이버 — 상품과 확인 수준 구분

- NAVER API HUB 공식 개요는 한시적 무료 제공, NAVER 검색 통합 월 775,000건, 키당 50 RPS 및 무료 기간 한도 증설 불가를 안내한다. 지역 검색의 상세 페이지에는 25,000회/일 문구도 남아 있어 문서 불일치가 있다. 실제 이용 시 콘솔/담당 확인이 필요하다. 지역 결과는 최대 5개, start=1 제약으로 많은 장소 탐색에 한계가 있다.
- Maps는 HUB 검색과 별도 상품이다. 공식 가이드는 대표 계정에 한한 무료 이용량과 종량제를 안내한다. Maps의 현재 상세 요금 원문은 페이지 동적 본문·조회 오류로 충분히 확인하지 못했다. 검색 색인의 숫자를 확정 가격으로 복사하지 않는다. Maps 단가·무료량·부가세·과금 차단/한도 조건은 재개 시 공식 가격 원문 또는 콘솔에서 확인한다.
- 2026-10-07 시행 NAVER API HUB 약관 개정 공지가 공식 목록에 있다. 상세 개정 원문과 10월 6일 적용본/7일 적용본은 아직 확보하지 못했다. 기존 개발자센터 약관을 HUB의 계약으로 대신하지 않는다.

네이버 개발자센터 약관의 임시 보관은 기기 24시간 또는 새 질의 중 짧은 기간, 서버 개인화도 같은 기준이며 서버 이력 조회는 최대 21일이다. 이것을 여행 계획의 장기 보관 허용으로 해석하지 않는다. 재개 시 HUB 적용 약관 확인이 우선이다.

카카오 담당자 스레드는 일부 저장 해석이 정정됐고 유료 서비스 조건에는 개별 설명을 요구한다. 타 서비스의 최종 답변을 이 앱의 허가로 간주하지 않는다. 저장 제한·기능 유료화 여부는 구체적인 여행 저장 흐름으로 확인해야 한다.

## 키·인증·서버 역할 제안

- Google 사용자 로그인과 지도 공급자의 앱 키는 별개다.
- 웹 SDK는 지정 JavaScript/웹 키와 등록한 사이트 origin을 사용한다. REST 비밀 키는 브라우저 번들/Vite 공개 환경 변수/Git에 넣지 않는다.
- 비밀 키가 필요한 검색·경로 API를 선택하면 로그인된 요청을 받는 최소 서버 중계가 필요하다. 선택 공급자의 CORS·인증·호출 제한·허용 origin 조건을 확인한 뒤 구현 계약을 만든다. Supabase Edge Function 등 런타임은 아직 선택하지 않았다.
- 프록시가 있더라도 결과의 저장·재배포 제한은 그대로 검토한다. 키를 감추는 기능으로 데이터 사용권 문제가 해결되지 않는다.
- 지도 엔진·공급자 플러그인·상시 범용 서버를 만들지 않는다. 외부 링크만 사용하는 역할은 내부 API 연동과 분리한다.

## 재개에 필요한 결정

1. 권장: 검색 후 바로 저장과 오프라인 계획 확인을 유지한다. 그 흐름을 허용하는 공급자/별도 계약/대체 공급자의 조건을 확인한 뒤 결정한다.
2. 대안: 초기는 사용자가 지도에서 직접 지정한 위치와 입력한 이름을 저장하는 흐름을 허용한다. 이는 R02/R05의 간단한 검색 추가 흐름 변경이므로 사용자 확정이 필요하다. 검색 결과 좌표를 다시 선택하는 우회로 저장하는 안은 허용 근거가 아니다. 선택 지도 SDK 자체의 좌표 보관 조건도 확인한다.
3. 별도 선택: 초기의 실제 길찾기를 네이버 지도 등 외부 앱에 맡길지, 앱 내부 도보/대중교통 경로·시간 조회까지 제공할지 정한다. 예정 경로를 단순 순서선으로 표시할지 실제 수단별 경로로 표시할지도 확인한다. 현재 요구를 임의 축소하지 않는다.

공급자에 문의 메시지는 발송하지 않았다. 문의를 하려면 사용자 승인과 구체적인 제품 설명이 필요하다. 선택 후 최신 약관·요금 원문 확인 → 역할/출처/보관 계약 확정 → T03/T07/T08 계약 갱신 → 문서 검증 및 PR 완료 순서로 진행한다. 그 전 T02 완료·T03 최종 설계·T04 구현으로 넘어가지 않는다.
